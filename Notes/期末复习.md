### 一、 核心运算律：逻辑简化的“武器库”

#### 1. 基础转换：摩根定律 (De Morgan)

这是处理“长非号”的唯一利器，**自外向里化简会比较方便**

- $\overline{A+B} = \bar{A} \cdot \bar{B}$
- $\overline{A \cdot B} = \bar{A} + \bar{B}$

#### 2. 项数压缩：包含律（冗余律/Consensus Theorem）

- **公式：** $AB + \bar{A}C + BC = AB + \bar{A}C$
- 核心特征： 1.  有两项各含有一个变量的原变量和反变量（$A$ 与 $\bar{A}$）。
  2. 第三项（$BC$）由前两项中剩下的变量组成。
  3. 结论： 这个“拼凑出来”的 $BC$ 项是多余的，可以删去。

#### 3. 变量消减：吸收律 (Absorption)

- **直接吸收：** $A + AB = A$（$A$ 的存在使得 $AB$ 毫无意义）。
- **消去因子：** $A + \bar{A}B = A + B$
- **分配律对偶形式**：$$A + BC = (A+B)(A+C)$$
  - *注：你笔记中这里写得很棒，利用 $(A+\bar{A})(A+B)$ 来拆解，这是理解这个公式最好的方式。*

### 二、 方法论核心：如何“凑”出简化机会？

你的笔记里提到了两种高级技巧，这体现了对逻辑函数结构的深层理解：

- **配项法：** 通过人为增加一项（如利用 $A+\bar{A}=1$）来创造出可以提取公因式或应用吸收律的条件。
- **吸收项法：** 识别出哪些项是其他项的“子集”，从而实现大面积的压缩。

**核心逻辑：** 所有的代数简化，本质上都是在寻找 **$X + \bar{X} = 1$** 或 **$X \cdot \bar{X} = 0$** 的机会。

### 三、 卡诺图法 (K-map)：视觉化的化简直觉

| **关键要素** | **核心逻辑与底层规律**                                       |
| ------------ | ------------------------------------------------------------ |
| **索引排列** | 必须采用 **格雷码 (Gray Code)**，即相邻格只有 **1 位** 变量不同。这是卡诺图能化简的基础。 |
| **圈组原则** | 圈的大小必须是 $2^n$（1, 2, 4, 8...）。圈越大，消去的变量越多。**四周延伸，最左面和最右面是相邻的** |
| **核心技巧** | **看变量是否“变脸”**：在一个圈内，如果一个变量同时以“原”和“反”两种形式出现，那它就是“不稳定”的，可以直接消掉。 |

## 简答题2-组合逻辑设计

### 利用MUX实现组合逻辑

+ 列出MUX的总布尔表达式 或者MUX的多路选择器
  + 能看到所有的最小项m0...ms
+ 分析逻辑函数中是**哪些最小项的和**
  + 其实就是将最小项转化为如001这样的数，其所代表的十进制数就是我要操作的$i$
+ 求出各个$D_i$ 的值或者信号
  + 最小项的$D_i$ 设为1或者C(**或者连接到额外的输入变量**) -- 
  + 其他为0
+ 注意：别忘了连接**非EN**（将0连接到上面）

如果使用**最小项 $m_i$** 来表示，MUX 的总布尔表达式如下：

$$Y = \sum_{i=0}^{2^n-1} m_i \cdot D_i$$

或者展开写成：

$$Y = m_0D_0 + m_1D_1 + m_2D_2 + \dots + m_{2^n-1}D_{2^n-1}$$

- **考点**：给你一个布尔函数 $F(A, B, C,D) = \sum m(1, 3, 5, 6)D$，让你用一个 8 选 1 MUX 实现。
- **解法**：
  1. 把变量 $A, B, C$ 接到 MUX 的选择端 $S_2, S_1, S_0$ 上。
  2. 根据函数要求的最小项编号，把对应的 $D_i$ 接高电平（1），其余接低电平（0）。
  3. 在这个例子中：$D_1, D_3, D_5, D_6 = D$，剩下的 $D_0, D_2, D_4, D_7 = 0$。

## 简答题4- MIPS汇编程序

+ **跳转指令的语义**
+ jr/jalr 是R型指令，j/jal 是J型指令
+ 立即数
  + 范围
  + 符号扩展：load/store指令，beq等b类指令，算术运算 addi
  + 无符号扩展：逻辑运算ori/andi  andiu（会触发溢出异常）


+ JAL语义
  + I: GPR[31]← PC + 8
  +  I+1:PC ← PC[GPRLEN..28] || instr_index || 00
  + 写入寄存器 需要加入一条31号寄存器选择
  + 注意延迟槽指令	所以是pc+8
+ J语义
  + PC ← PC[GPRLEN..28] || instr_index || 00
  + 注意虽然instr_index是26位立即数，但由于每个指令占4个字节，因此跳转范围为2^28 = 256MB
  + 与jr对比，在4GB中划分16个256MB的区域，在当前PC范围里跳转
+ JR语义
  + I：PC ←GPR[rs]
  + rs是32位，因此跳转范围2^32 = 4GB
+ 
+ BEQ语义
  + I: target_offset← sign_extend(offset || 00)
    +  condition← (GPR[rs] = GPR[rt]) 
  + I+1: if condition then PC← PC + target_offset endif
+ 尤为关注A3输入源：rt/rd/31
  + R型三操作数的如add/sub/sll等指令需要写入rd
    + 如 `add rd,rs,rt`一定注意rd在指令上出现在第一个位置
  + I型指令，含立即数的，通常写入rt
    + 如`ori rt,rs,imm`

寻址方式

+ 立即寻址：op rs rt imm16 立即数作为操作数
+ 寄存器寻址： op rs rt rd shamt funct

+ PC相对寻址 op rs rt imm16 立即数作为形式地址（相对PC的偏移）beq

### TIO的一般计算方法（重点！）

**设主存地址位数为A，n路组相联cache**

​	$Cache组数 = \frac{Cache数据大小}{块大小\times n路}$

​	$主存组数 = \frac{主存数据大小}{cache组数\times n路}$ 主存**以cache组数个块**为一组（放置时是取模逻辑）

+ Offset = $log_{2}块大小$ 向上取整

+ **Index = $log_{2}Cache组数$** 向上取整

  + Cache一般标注的总大小指的是**数据的大小**

    

+ **Tag = A - I - O，即剩余的头部位数**

+ $Cache总容量 =  cache块数×(数据位数+ Tag位数+ Valid位数) = 2^{index} \times (8\times2^{offset} + Tag + 1)$

**大小单位都取byte，块大小的值就是以byte为单位的值**

## 简答题9 辅存-硬盘

#### 例题

##### (1) 容量计算：数清楚“房间”总数

**一定注意每个盘有两个面，最外两侧盘面不能记录（2 * n - 2)**

$$容量 = 有效盘面数 \times 每面磁道数 \times 每道扇区数 \times 每个扇区大小$$

##### (2) 平均寻址时间：物理等待的总和

**平均寻址时间** = **平均寻道时间** + **平均等待时间（旋转延迟）**。

- **平均等待时间**：**磁盘转半圈的时间。**
  - 转一圈时间T = 1/f = $60\text{ s} / 7200\text{ rpm} = 1/120\text{ s} \approx 8.33\text{ ms}$。
  - **注意是rpm 一分钟多少转！**
  - **等待半圈 =** $8.33 / 2 = 4.165\text{ ms}$。
- **总时间**：$8 + 4.165 = 12.165\text{ ms}$。

##### (3) 数据传输率：一秒能读多少位

传输率取决于**磁盘转多快。**

- **计算**：每秒转数（$7200\text{ rpm} = 120\text{ r/s}$）$\times$ 每个磁道的数据量（$12 \text{ 扇区} \times 512 \text{ 字节} \times 8 \text{ 位}$）。
- **结果**：$120 \times 12 \times 4096 = 5,898,240\text{ b/s}$。
- **注意是多少位，需要×8**

##### ***注意**：**一定要看清单位是 Bytes 还是 bits，时间是 $ms$ 还是 $s$***

+ ***看清楚是盘片还是盘面** 盘面 = 盘片×2*

## 📖 存储体系计算逻辑笔记整理

这份笔记主要围绕 **Cache**、**TLB** 和 **页表（Page Table）** 的结构分析与参数计算展开。

### 1. Cache 相关计算

这是关于 CPU 缓存如何映射主存地址的逻辑。

- **① 计算组数 (Sets)：** $\text{组数} = \frac{\text{Cache 有效数据大小}}{\text{Cache 块大小} \times n\text{路}}$
- **② 计算块内偏移 (Offset)：** 对应地址中的低位。
- **③ 计算组地址位 (Index)：** 对应地址中的中间位，位数为 $\log_2(\text{组数})$。
- **④ 分析块结构 (一项)：** * 通常包含：Tag（标记位）、Index（索引）、Offset（偏移）。
  - 图中简写为：`[ Tag | I | O ]`
- **⑤ 主存组数：** 涉及到主存与 Cache 的映射关系。

### 2. TLB (Translation Lookaside Buffer) 相关计算

TLB 是页表的“快表”，计算逻辑与 Cache 类似。

- **计算组数：** 逻辑同 Cache。
- **块内偏移：** 无（笔记备注：一页就是一块）。
- **计算组地址位：** $\log_2(\text{组数})$。
- **分析表项结构：** * 输入通常是 **VPN** (Virtual Page Number)。
  - 结构：`[ Tag | Index ]`

### 3. 页表 (Page Table) 相关计算

涉及虚拟地址（VA）到物理地址（PA）的转换。

- **计算页数：** * 公式：$\lceil \frac{\text{VA 空间大小}}{\text{页大小}} \rceil$
  - 或$2^{\text{VPN 位数}}$。
- **计算页内偏移 (Page Offset)：** 对应地址的低位。 $\log_2(\text{页大小})$。
- **计算 VPN / PPN：** * $\text{总位数} - \text{页内偏移}$。
- **分析 PTE (Page Table Entry) 结构：** 页表项的具体组成。
  - 结构`[Valid | AR | PPN]`
